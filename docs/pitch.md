# 3-minute pitch script

One person speaks, one drives the laptop, and a third hands a tablet open at `/play` to a judge. Open every screen from the live site, https://bbfutaba.github.io/below-threshold/ (not a local dev server: the leaderboard's QR code points at the site the tab came from), each in its own tab, in this order: `/`, `/learn/superposition`, `/learn/qft`, `/learn/shor`, `/learn/noise`, `/play`, `/realtime`, `/lab`, `/honesty`, `/leaderboard`.

Before you start:
- In `/learn/noise`, press **Run 200 shots** once with **Error rate per qubit per step** at *none (perfect qubits)*, so the clean peaks are already on screen.
- After rehearsing, reload `/learn/shor` (its first **Run to the end** is seeded and factors 15) and reload `/play` on both the laptop and the tablet so they show the same seeded puzzle. If the **How to play** walkthrough appears (only on a device's first visit), press **Skip**.
- Leave `/realtime` open until all three decoder lanes show a measured time (**Start the clock** stays disabled until then).

If the live demo fails, the fallback is the narrated 3-minute pitch video: open the **Film** page (`/film`), where it sits at the top under *The project in 2:52*, and press the section button for where you were (**The problem**, **Learn: from a qubit to Shor's algorithm**, **Play: error correction and the decoder**, **Prove: the lab, the checks, the close**). Offline, the same video is `docs/media/below-threshold-pitch.mp4`. The older backup video, `docs/media/demo.webm`, is a silent 1:35 screen recording of the error-correction screens only, made before the Shor chapters existed. Keep both one click away.

## Delivery tips

- Rehearse the full run at least five times with a timer. If you run long, drop the qubit beat (0:20–0:32) and give its time to the game.
- If a judge asks a question mid-demo, answer in one sentence and continue; save depth for Q&A.
- Close with one takeaway: **"Error correction works, but only if decoders keep up."**
- Shor runs are random: after the first (seeded) run, some end in **This run failed** (an unlucky measurement). If that happens on stage, say it is part of the algorithm, press **New run ↻**, then **Run to the end**.
- If the lab is slow on the demo laptop in rehearsal, press **Run experiment** in the `/lab` tab before going on; the curves stay in the tab, and on stage you only drag the noise level.
- If anything breaks on stage, switch to `/film` and press the pitch section you were in; the narrated video (2:52, recorded by the team) carries the rest.
- Numbers to have ready: thresholds 9.94% (bit flip, MWPM; published ≈ 10.3%; Stim + PyMatching 9.85% on the same check), 2.84% (with measurement errors; published ≈ 2.9%); MWPM ≈ 100 µs per round and union-find ≈ 4 µs at d = 9, p = 3% (`npm run bench`; real-time mode re-measures them live in the browser); hardware ≈ 1 µs per round; PyMatching cross-check: same minimum weight on 100% of 90,000 instances; code layout equal to Stim's for d = 3 to 11; 125 unit and 66 end-to-end tests.
- The noise beat's numbers are ballparks: "once in a thousand" is CITATIONS.md item 13, and "once in a trillion" has no source entry yet (the film says it too, but item 18 backs only the qubit count and run time). Confirm both against a current source before presenting.
